## 0. 上传前必须先做的两件事

### 0.1 描述被解析成了 `>-`(已修,但要重新打包上传)

上传页提示「检测到 SKILL.md 中的描述:`>-`」。原因是 frontmatter 用了 YAML 折叠块:

```yaml
description: >-
  查询某个网站在 AI 引擎…
```

`>-` 是 YAML 的多行折叠语法,**平台的解析器没展开它,把符号本身当成了描述**。
已改成单行双引号写法,重新生成的包里不会再有这个问题:

```yaml
description: "查询某个网站在 AI 引擎(豆包/DeepSeek/千问/元宝/文心/Kimi 等)里的可见度,…"
```

👉 **请用重新打包的 zip 再传一次**,然后在「检测到描述」那里点「使用此描述」——
自动抓到的和下面第 4 栏要填的是同一段,不用手抄。

### 0.2 传 zip,不要选文件夹

这次上传显示「已选择 4 个文件」且没有目录层级,说明文件夹选择把结构**拍平**了。
SKILL.md 正文里指向 `references/endpoints.md`、`scripts/vtag.sh`——拍平之后这两个路径不成立。

```bash
cd /home/DEV/Geo-Analytics-Skill
tools/pack.sh          # → dist/vtag-geo-analytics-0.1.0.zip(6 个文件,13 KB)
```

zip 里的结构(SKILL.md 在**根目录**,平台的硬要求):

```
SKILL.md
scripts/vtag.sh
references/endpoints.md
references/metrics.md
```

> 退一步说,**就算平台仍然拍平,skill 也不会失效**:端点表、指标公式、口径红线
> 全在 SKILL.md 正文里,`references/` 只是展开版。但能带结构就带,别主动丢。

```
vtag-geo-analytics
```

- 与 SKILL.md 的 `name` 一致,小写字母 + 连字符,符合「仅允许小写字母、数字和连字符」;

## 4. 描述

点「使用此描述」即可(与 SKILL.md 一致)。若要手填,原文:

```
查询某个网站在 AI 引擎(豆包/DeepSeek/千问/元宝/文心/Kimi 等)里的可见度,以及 AI 带来的站点侧流量与转化。用于回答「我的品牌在 AI 回答里露出多少」「AI 来源带来多少会话和转化」「哪些页面被 AI 引用」这类问题。首次使用会引导用户在浏览器里完成一次授权。
```

**别改成「专业的 AI 分析工具,提升您的品牌影响力」这类。** 描述是这个 skill 唯一的触发面:
对面的 agent 靠它决定要不要调用,写成形容词它永远不会被触发;平台的审核意见里
「描述过于模糊」也是常见驳回原因。这段话里每一句都是用户会说出口的问法。

## 5. 分类(多选)

按平台实际给的分类列表挑,优先级从高到低:

1. **数据分析 / 分析统计** —— 主分类,这是个报表取数 skill;
2. **营销 / 增长 / SEO** —— 实际买单的人在这里(关心「品牌在 AI 回答里露出多少」);
3. **开发者工具**(如果有)—— 它本质是调 API。

选 2~3 个即可,别把不相干的分类全勾上——分类勾错会拉低召回质量,平台也会看。

## 9. 审核不通过的常见原因(平台原文)与我们的对应

| 平台列出的常见原因 | 我们这边 |
|---|---|
| SKILL.md 格式不规范 | frontmatter 已改单行描述;正文是标准 markdown |
| 缺少测试案例 | ⬜ **有缺口**:平台建议发布后补 3 个效果案例。发布成功页里点「对话式补充案例」 |
| 定价明显不合理 | 免费,不涉及 |
| 描述过于模糊 | 描述写的是具体问法,不是形容词 |

### 发布后要补的 3 个效果案例(建议这么写)

1. **「我们的品牌上周在豆包里露出多少?」** —— 调 `/engines`,读引擎侧的露出率与文章引用率,
   并说明 `probes=0` 时返回 `null` 而不是 0%;
2. **「AI 来源带来了多少会话和转化?」** —— 调 `/acquisition?dimension=engine` + `/conversions`,
   并说明 `(external)` 这一档是「来源被抹掉」,不能算成某个引擎;
3. **「哪些页面被 AI 引用、带来了流量?」** —— 调 `/pages` + `/probe-events`,
   演示「引擎侧与站点侧分开呈现、不做因果换算」这条红线在回答里长什么样。

第 3 个案例最值得写:它演示的恰恰是这个 skill 与「随口编一个归因」的区别。
