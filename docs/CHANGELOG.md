## 1.0.2 —— 2026-08-24

**只改发布页的显示名,包内容与 1.0.1 逐字节相同**(除 frontmatter 的 `version`)。

发 1.0.1 时显示名被写成了字面的 `Publish` —— `clawhub skill publish <path>` 在没有
`--name` 时**从文件夹名推导显示名**,而当时传的是一个叫 `publish` 的暂存目录。
干跑复现两次确认与 `--no-input` 无关,就是 basename。

📌 **教训**:这个 CLI 的显示名不来自 `SKILL.md` 的 `name:`,也不来自正文标题,
而是来自你传给它的那个路径。以后发布**一律显式带 `--name`**,并且暂存目录就叫
包名,别叫 `publish` / `dist` / `tmp` 这类词。

显示名定为 `Geo analytics & AI visibility`(首次上架时那个,与 slug `geo-analytics`
对得上)—— 包内 `name: vtag-geo-analytics` 与正文标题 `# Vtag GEO Analytics` 未动。

发布表单粘这一段:

```
修复发布页显示名(1.0.1 误显示为 "Publish")。包内容与 1.0.1 相同,已安装的用户无需更新。
```

## 1.0.1 —— 2026-08-24

⚠️ **为什么不是 1.0.0**:clawhub 上 `1.0.0` 这个号 08-21 就被占了(平台侧的默认号,
包内 frontmatter 其实写着 `0.1.0`),而且那份已经有 23 次下载。**已发布的版本不可变** ——
把不同内容塞进同一个号,装过的人手里的「1.0.0」和后来者的「1.0.0」就不是同一个东西,
出问题时谁也说不清对方装的是哪份。所以本次发 1.0.1,让 `update` 正常拿到。

📌 那个 `1.0.0` 的内容比本仓库的 0.1.0 **还老**:frontmatter 里还是 `description: >-`
折叠块(cb44944 修掉的那个坑)和改写前的旧描述。说明当时传上去的 zip 不是当时的 HEAD ——
**打包与发布之间隔了几次提交,没人对过**。`pack.sh` 现在打的是工作区,发布前跑一次
`git status` 确认干净,是这条的补救。

升 1.0.0 的条件是本文件自己定的:「端到端对数过了再发 1.0.0」。2026-08-24

### 1.0.0 相对 0.1.0 的实际改动

- `LICENSE`:仓库根补 MIT-0(frontmatter 一直写着「见仓库 LICENSE」,而那个文件不存在),
  `pack.sh` 打包时复制进 zip 根目录 —— 仓库只留一份,不留会漂的抄件;
- 限速那句改成实测口径:原文写「每分钟 60 次」,实测串行 66 次不触发。
  服务端按**每进程**每分钟 60 次计,生产多进程,实际约 120 次/分钟。
  写死一个数会让 agent 以为那是硬边界,而它随部署形态变;
- 端点契约、指标公式、口径红线**一个字没动** —— 「发布过的端点只加不改」。

### 内部改动记录(不进发布说明)

- `SKILL.md` 的 `description` 从 YAML 折叠块 `>-` 改成**单行双引号**:skillhub 的解析器
  不展开折叠语法,上传时抓到的描述是 `>-` 这两个字符本身;
- 描述重写:钩子 → 引擎名 → 差异化 → **诚实条款(识别不出的如实标「来源未知」)** →
  三句用户原话(agent 的触发面);
- `tools/pack.sh`:打包时 `cd` 进包目录,保证 `SKILL.md` 落在 zip **根目录**,打完自校验;
- `tools/gen_endpoints.py`:端点表与 `SKILL.md` 里的摘要表都从后端 `reports.py` 生成。

## 版本纪律

- **发布过的端点只加不改** —— 装出去的是快照,我们改端点它不会跟着改。加参数、加响应
  字段可以;改字段含义、改参数名、删端点不行,要改就发新版本,老版本继续能跑;
- 端点有任何变化 → 跑 `tools/gen_endpoints.py` → bump `version` → 在这里记一条;
- **`version` 只在 `SKILL.md` 里改**,本文件与发布表单都是抄件。
